# ランドマーク数と対局時間の簡易比較

2026-09-29に、基本4種と全6種のランドマーク設定でCPU対局の長さを比較した。初回プレイの標準設定を変える判断材料にする前に、レビューで示された「全6種の方が約3割長い」という推定が、人数とCPU構成を変えても再現するかを確認した。

## 方法

- 1条件50戦、合計400戦。全戦で同じseed範囲（`20260929`から開始）を使い、基本4種と全6種を同じseed同士で対応させた。
- 人数は2人・4人。CPU構成は全員Normalと、Normal/Strong混成の2種類。
- 混成戦の座席は `selfplay.js` の通常のlineup rotationで回した。
- 基本4種は駅・ショッピングモール・遊園地・電波塔。全6種はそこに港・空港を加えた。
- 対局時間の代理指標は `GameManager.turnCount`。プレイ時間（分）ではなく、ルール上の手番数を数える。
- 差の区間は、同じseedの「全6種 − 基本4種」の差を20,000回再標本化した対応ブートストラップ95%区間。
- 全条件で最大ステップ到達による打ち切りは0件。各実行のピークRSSは約83〜142MB。

## 結果

| 人数・CPU構成 | 基本4種 平均手番 | 全6種 平均手番 | 対応差（95%区間） | 中央値の対応差 |
| --- | ---: | ---: | ---: | ---: |
| 2人・Normal/Normal | 60.14 | 62.30 | +2.16（−3.52〜+9.48） | +1.5 |
| 4人・Normal全員 | 91.68 | 93.32 | +1.64（−2.84〜+6.02） | +2.0 |
| 2人・Normal/Strong | 64.50 | 66.50 | +2.00（−3.46〜+7.54） | −1.0 |
| 4人・Normal/Strong混成 | 73.58 | 81.94 | +8.36（+3.62〜+13.00） | +8.0 |

## 判断と限界

この条件では、全6種がいつも長いとは言えない。差はCPU構成と人数に依存し、全員Normalおよび2人混成では区間が0をまたいだ一方、4人混成では全6種が長くなる結果だった。2人戦の初回設定を約3割短縮するとした先の簡易推定は、これらのCPU条件では再現しなかった。

50戦ずつのCPU自己対戦は実際の人間同士・人間とCPUの遊び時間を測っていない。勝ち方やカード選択もCPU方策に左右されるため、初回設定や既定ランドマーク数はこの結果だけで変えない。実ユーザーの所要時間・途中離脱や人数別プレイ感を別に観測してから判断する。

再現コマンド例（出力先は各条件で別ファイルにする）:

```sh
node scripts/selfplay.js --games 50 --seed 20260929 --max-steps 5000 --format json --landmarks '駅,ショッピングモール,遊園地,電波塔' normal normal
node scripts/selfplay.js --games 50 --seed 20260929 --max-steps 5000 --format json --landmarks '駅,ショッピングモール,遊園地,電波塔,港,空港' normal normal
node scripts/selfplay.js --games 50 --seed 20260929 --max-steps 5000 --format json --landmarks '駅,ショッピングモール,遊園地,電波塔' normal strong normal strong
node scripts/selfplay.js --games 50 --seed 20260929 --max-steps 5000 --format json --landmarks '駅,ショッピングモール,遊園地,電波塔,港,空港' normal strong normal strong
```
