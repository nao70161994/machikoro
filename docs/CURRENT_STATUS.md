## 現在の構成

- バニラJavaScriptのbrowser-global構成です。`index.html`がクライアントの読み込み順を定義し、`tests/runtime-dependencies.test.js`が主要な依存と読み込み順を検証します。ルールは`GameManager`、実行状態はruntime adapter、描画はUI helperとcomposition rootに分かれています。
- オンラインの検証・アクション生成・replay・snapshot・再接続はクライアントと`server/`の専用モジュールが担当します。待機室の見た目を変える際も、サーバー上の席とプレイヤー対応を変えません。
- 見た目は`style.css`、施設・街の描画は`js/uiBuildMenu.js`、広場のカメラ・HUDは`js/plazaField.js`が中心です。既存テーマの切り替えを維持します。
- 静的検査は`npm run test:static`、通常の回帰テストは`npm test`。追加のオンライン・PWA・release・WebKit検証は変更の影響範囲に合わせて実行します。

## 完了済みの基盤改善

1. 広場の全体表示でも発展度・都市の個性・ランドマーク・プレイヤーを判別できる街の表現。
2. 勝利画面で達成感を遮らず、引き続き利用できるPWA更新・システム通知。
3. 2～10人の参加者・席・準備状態を見渡せるゲームロビー。
4. 「育てた街」の複数建物と「×N」の総数表示による重複・重なりの解消。
5. 変更箇所の依存関係・CSS・テストを、実際の保守上の問題に応じて整理。

関連するユニットテスト・静的検査・Chromium画面確認・実装担当以外の再レビューは実施済みです。Chromiumではローカル対局中の更新保留とタイトル復帰後の更新、オンライン待機室の再起動後の更新、キャッシュ削除とオフライン表示も確認しました。CIの成否は上記コマンドで対象コミットに対応する結果を読み、実装一覧だけでgoalの完了を判定しません。

## 残る確認と次の優先候補

- 広場の情報伝達と演出を改善するgoalが進行中です。既存の探索・ズーム・パン・多人数対応を保ち、以下の8項目を実装しました。最新CIの成功を確認するまでgoalは完了扱いにしません。
    1. 出目・発動施設・収支・支払い元と先を、画面外の施設も含めて追える短いサマリー。
    2. 大収入・支払い・コンボ・追加手番・振り直しなど重要な出来事に限った強調。
    3. HUDからすぐ開ける主要施設の内訳と所有枚数。
    4. 全体ビューで初期・中盤・成熟した街と産業差を比較できる表現。
    5. 正本のルールに基づく出目別純収支と、条件・未確定効果・確率を区別した情報。
    6. 市場での購入から街の建設位置・建物・周辺の成長までつながる手応え。
    7. 普通の施設より明確なランドマーク完成の達成イベント。
    8. ログを閉じたまま重要な出来事を理解できる操作と自動ブラウザ検証。
- 実装済みの変更: 出目・確認できた収支の短い表示、HUDの施設内訳、明示操作による出目別試算、購入と目標達成の強調を追加しています。特殊効果の金銭ログは個別記録と合計が混在するため、推測で足し合わせず未集計の原文として残します。試算は選択効果前の即時純収支で、振り直し・追加手番・将来の建設は含みません。
- 5〜10人の全体ビューは市場の周囲へ実寸に応じて配置し、縦長で街が小さくなる問題を改善しています。2〜4人の既存配置を保ち、世界の幅と高さにカメラ制限・全体表示を合わせます。結果内訳の展開とフォーカスは同じ結果の再描画で維持します。
- 強制カメラ移動や演出待ちを増やさず、Reduced Motion・キーボード・音と振動の設定を保ちます。収支閲覧は実状態や乱数を変更しません。
- 初回実装では、ユニットテストと静的検査、Chromiumの320/390px縦持ち・844px横持ち・1440pxで4/10人の結果表示、試算時の状態不変、条件保持、建設・目標達成を確認しました。画面離脱・再開・勝利時の清掃と、実ルールの電波塔・追加手番表示も確認しました。初回CIのrelease・CPUは成功しましたが、WebKitでは非表示の操作を含めたテストと横持ちの出来事展開手順が失敗したため、実UIの操作経路に修正しています。修正後の最新CIは引き続き確認が必要です。45e29c7e時点で全8項目を対象にした実装担当以外の再レビューは追加指摘0件でした。0コインの送金で相手名が欠落する問題も修正済みです。

## 意図的な制約

- 無料運用を優先します。`canonicalStateStore`にはnoop・memory・fileの実装がありますが、永続ボリュームのないホスティングでプロセスをまたぐ永続正本を保証するものではありません。無料運用を理由にDB導入を追加しません。
- CSPの運用状況と強制適用の条件は[運用手順](OPERATIONS.md)、復元の信頼境界は[オンライン同期](ONLINE_SYNC.md)を正本とします。
- ES Modulesやフレームワークへの全面移行、巨大ファイルの機械的な一括分割、CPUの新しい性格の追加は今回の前提にしません。
- 人間への定型的な実機確認依頼を避け、自動ブラウザ・CIを利用します。自動検証した画面を実機確認済みとは表現しません。未検証範囲は検証報告に残します。
