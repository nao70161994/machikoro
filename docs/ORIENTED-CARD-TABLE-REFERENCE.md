## 公開実画面で観察できること

| 対象 | 観察 |
| --- | --- |
| 手前の所有カード | 読み手に対して正立0° |
| 奥の所有カード | 手前に対し180°。奥の席に座る人から正立する向き |
| 左右の所有カード | 左は＋90°、右は−90°。カード上端が卓中央へ向く |
| ランドマーク | 所属席の施設カードと同じ向き。施設列より卓中央寄りの列に置かれる |
| 中央市場 | 手前の閲覧者に対し正立0°。周囲の所有カードと向きが異なる |
| 席の境界 | 大きな独立パネルで囲う代わりに、卓の四辺、カードの方向、施設とランドマークの列、外側HUDとの対応で理解させる |

PV65/68秒は序盤の四辺配置。72/76秒は中央ダイス/収益イベント中も席の向きを保つ。78秒は所有物が増えた状態でも四辺配置を維持する。79〜83秒は購入ランドマークが卓上に正面の大きなカードとして浮き、背景の席と市場は残る。

85秒の勝利フレームは手前ランドマーク側が大きく見える。ただしPVには編集があるため、これを連続したカメラ移動の操作証拠とはしない。任意の相手席を選んでカメラが正面へ回転する機能、回転時間、ズーム操作の方法は、この画像群から確認できない。

## mainとの差と以前の判断の撤回

main205be605は全カードを観客に対して正立させ、カード群を左右/上下の領域へ並べている。`js/cardTableCamera.js` のmain版はパンと拡大を持つが、角度や席を正面化する回転を持たない。このため全員のカードが存在していても、四人が同じ卓を囲む身体的な方向の表現が弱い。

以前のREFERENCEにあった「正立カード＋座席位置でも同卓感を出せる」という推奨は、公式観察の事実ではなく実装側の判断だった。新しいユーザー指示が求める実卓の向きを満たさないため撤回する。精読性は通常盤面の向きを消すことで解決せず、閲覧カメラで解決する。

## 新Goalの採用判断

以下は公式で確認済みの操作仕様のコピーではなく、観察した実卓構造と今回のユーザー要求を満たすためのダイスシティの設計判断である。

1. 通常全体盤面は手前0°、奥180°、左右±90°を持つ。施設とランドマークは同じ席の向きを共有する。
2. 席を閲覧する時は、その席の角度と逆向きにカメラを回し、施設を正立・適切な倍率で読む。元の施設カードを別パネルへ複製して主盤面を置換しない。
3. 中央市場は通常の卓座標で0°。市場へ移動する操作ではカメラを0°へ戻し、市場が正立することを一貫させる。
4. 閲覧終了時は倍率・位置に加えてカメラ角度も復元し、元の席の関係と視点へ自然に戻る。
5. 固定HUD、ダイス、発動/送金の説明は読める画面向きを維持し、卓カメラの回転と独立させる。Reduced Motionでは視点変更を即時適用し、ゲーム状態やCPU待機へ回転を結びつけない。

最大の改善点は、施設を同じ方向に並べた情報一覧から、席の向きを持つ実卓へ戻すこと。正面閲覧カメラとの往復によって、同卓感とカードの読み取りを同時に成立させる必要がある。完成判断は変更後の実画面と操作で行い、回転CSSの存在だけで達成としない。
