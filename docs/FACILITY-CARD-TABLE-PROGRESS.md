## まとまった検証と修正

- 320pxのブラウザ操作ケースは成功（全体/拡大/キーボード移動/席移動/テーマ切替/終盤fixture、ローカル実行2.5分）。その後のportrait配置更新とDOM復元修正はCIで再確認する。
- npm testを一括実行し、checkJs対象とlint対象のファイル集合不一致を1件検出。新カメラをtsconfigの明示対象へ追加し、該当設定テストと所有カード描画テストを再実行して成功。全体成功とはまだ扱わず、CIで全件を再確認する。
- static checkerは812 JavaScript/41 JSON成功。変更した製品JSのESLint成功。型検査は4composition root成功。
- 独立コードレビューでテーマ離脱の早期return不備を発見し、wasMountedで元の状態を保存してDOM復元を実行するよう修正。テーマごとの操作パネルの実際の親/可視性を既存ブラウザケースへ追加。
- v8で320pxの所有者領域分離と844px市場の先頭行全体を目視確認。320/844とも実DOM購入で施設枚数2→3、残高12→11を確認。
- 制御fixtureで名前と手番を変更した後も古い開始ログが残っていたため、v8建設HUDの購入者表示は自然対局の証拠に使わない。fixtureの開始ログを状態へ合わせ、購入者/施設名の検証を追加。製品のルールやログを書き換えて隠していない。
- 320pxの市場への移動は中央寄せで先頭カードが欠けていたため、卓より幅が狭い端末では市場左端へ移動するよう変更。次の操作検証で確認する。
- 承認された自作画像4枚を docs/design-review/2026-10-15-facility-card-table/ に保存。公式画像は研究用のignored artifactsだけに保持しゲーム資産には追加しない。

主要なレイアウト問題は改善したが、自然対局完走・時系列演出・終盤/多人数・オンライン等の最終確認は継続する。CIの手動実行へ縦/横の自然UI対局を追加し、スマートフォン側で重いブラウザを並列起動しない。
