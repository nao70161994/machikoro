# 戦略の異なるRL CPUを増やすための学習パイプライン

## 目的

同じ強いモデルのシード違いだけではなく、**戦略の異なる選択可能なAI** を作るため、報酬 shaping と人数を変えた6系列を並列学習します。既存の Actor-Critic / JS CPU評価 / browser 形式モデルを利用し、ゲーム本体や公開中のポートフォリオは変更しません。

GitHub Actions の **RL Strategy Diversity Training → Run workflow** から手動で実行できます。定期実行や push 自動実行はありません。同時3ジョブを上限とし、途中学習の重みは 25 試合ごとに保存、試合数 250 ごとに軽量評価します。1ジョブの学習上限は4時間で、完走しなかった場合も最後の途中保存が artifact に残ります。

| 実験ラベル | 人数 | 学習ゲーム数 | 学習率 | 仮説 |
|---|---:|---:|---:|---|
| landmark | 2 | 2,000 | 2e-5 | ランドマーク早期建設に寄せる |
| economy | 2 | 2,000 | 1e-5 | 収益を生む青・緑のエンジンを優先 |
| interaction | 2 | 2,000 | 2e-5 | 赤・紫の干渉カードと相手の損失を重視 |
| harbor | 2 | 2,000 | 1e-5 | 港・漁船など港湾系の開発を促進 |
| four-engine | 4 | 500 | 1e-5 | 多人数の収益エンジン型 |
| four-interaction | 4 | 500 | 1e-5 | 多人数の干渉型 |

合計 9,000 学習ゲーム。各モデルは独立した乱数初期化から学習し、シード・人数・学習率を異なる実験メタデータに残します。4人戦の `train-batch-size=1` は2人戦のバッチと更新規模が異なります。

## 強さと多様性の判定

学習中の best 選抜は JS 版 CPU に対する各2試合の軽量評価であり、**それだけでは採用しません**。完了後、2人戦モデルは weak/normal/strong の各60試合、4人戦モデルは2種類の4人 lineup で各80試合を独立評価し、勝率だけでなく購入したカード・ランドマークの分布、赤・紫カード率、青・緑カード率、平均ターン数、pass率を比較します。

- 戦略ラベルが異なっても、購入傾向が実際に分かれなければ別スタイルとして採用しません。
- 既存採用モデルと同じ seed / 席順を固定した100〜300試合の追加評価、AI同士のhead-to-head、特殊カードとPython/JS parityの検証を経て採用判断します。
- 2人用と多人数用はモデル入力状態次元が異なるため、混在させずに評価します。
- 強さと戦略の多様性を別指標とします。**弱いが特徴的なモデル** はAIの難易度・特徴を明示して扱い、最強AIを自動的に置き換えません。

選抜後に `models/rl_model/portfolio/` と `registry.json` に追加し、プレイヤーが戦略を選択できるUIを実装する段階へ進みます。このPRは学習パイプラインのみで、まだ新しいモデルを公開・追加しません。

## 成果物

各学習実行の Actions の Artifacts から `rl-strategy-<kind>-<run_id>` を取得します。
`best_model.browser.json` は評価対象の候補、`model.progress.browser.json` と `.npz` は学習途中または最新の重みです。`strategy-eval.json` があれば、実戦での強さとカード傾向の評価結果が含まれます。artifact の保持期間は30日なので、良いモデルは期限内に採用・別保存する必要があります。
