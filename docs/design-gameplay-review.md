# デザイン・ゲーム体験レビュー記録

## 2026-09-29: ランドマーク数と対戦時間

4ランドマークと6ランドマークのCPU対戦を、人数別に同じseed範囲で100試合ずつ評価した。シミュレーションには`script/selfplay.js`の`runSeries`を使い、全員を通常CPUに固定した。4ランドマーク条件は`駅・ショッピングモール・遊園地・電波塔`、6ランドマーク条件は`港・空港`も加えた全施設。最大ステップ数は2,000。全1,000試合が完走し、ステップ上限到達はなかった。

`turnCount`は各プレイヤーが手番を終えるごとに増える。ラウンド換算は比較用に平均ターン数を人数で割った概算で、途中参加や追加手番の影響を均す厳密なラウンド数ではない。

| 人数 | 4施設 平均ターン | 6施設 平均ターン | 6施設の差 | 4施設 P50 / P90 | 6施設 P50 / P90 | ラウンド換算 4 / 6 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2人 | 64.31 | 63.16 | -1.8% | 64 / 81 | 63 / 77 | 32.16 / 31.58 |
| 3人 | 81.17 | 80.95 | -0.3% | 79 / 99 | 80 / 95 | 27.06 / 26.98 |
| 4人 | 92.36 | 98.19 | +6.3% | 93 / 112 | 98 / 112 | 23.09 / 24.55 |
| 6人 | 108.97 | 122.27 | +12.2% | 109 / 129 | 122 / 142 | 18.16 / 20.38 |
| 10人 | 134.90 | 160.28 | +18.8% | 136 / 152 | 160 / 188 | 13.49 / 16.03 |

同じseed範囲は両条件に使ったが、ランドマーク構成が変わるとゲーム内の乱数消費が変わるため、試合単位で結果が対応する完全なペア評価ではない。測定中のNode RSSは約99〜180 MBの範囲で、異常な増加やゲームの枯渇は観測しなかった。

### 判断

- 2〜3人戦では6施設の平均ターン数はほぼ変わらず、今回の条件ではわずかに短かった。
- 4人以上では6施設にすると平均とP90が伸び、その差は人数が多いほど大きくなった。
- この評価は通常CPU同士のシミュレーションであり、人間同士の体感時間、異なるCPU構成、オンライン待ち時間は測っていない。レビュー内の簡易推定とも条件が異なるため、既定ランドマーク数は変更しない。
- 初回向けに4施設を推奨するかは、2〜4人および多人数の実プレイで理解しやすさと長さを確認してから決める。
