# デザイン品質レビュー記録

## 対象と前提

- リポジトリ: `nao70161994/machikoro`
- 対象テーマ: にぎわい広場
- 実施日: 2026-10-09
- 比較基準: 「みんなと街コロ」の完成度。固有アートやキャラクターは使用しない。
- 実ブラウザ確認: Termux 上の Chromium headless を CDP で操作。844×390 の画面エミュレーションであり、物理スマートフォンの実機確認ではない。

## 改善・再レビュー 1

### 発見した問題

844×390 の旧横持ちレイアウトは、4人分の座席を固定位置に押し込み、上下プレイヤーのカードを小さくしていた。左右に余白がある一方、市場とカードの視認性も不足していた。

### 実施した改善

- 761〜1024px、横向き、480px以下では、全プレイヤーの要約を横スクロールの名簿に集約。
- 自分と選択中/手番中プレイヤーの街を表示し、他プレイヤーは名簿選択で切り替え。
- 市場と操作/出目表示を独立した領域に配置し、施設アートを表示。
- 名簿選択ではゲーム状態を変えず、最大2つの街だけを表示する。

### 実画面でのレビューと修正

初回スクリーンショットでPWAインストール案内の状態がゲーム領域を縮める条件を再現した。テスト画面ではインストール案内を正規の dismiss API で閉じ、実際のアプリ動作と fixture の初期状態を混同しないようにした。さらに初回画面では操作ボタンが左端に偏っていたため、操作列を全幅の横スクロール領域にし、各設定項目に明確なボタン面を与えた。

10人戦の密度確認では、個別UIが追加する `#playerNavigation` がインライン `display` によって隠れず、盤面の下端に重なる問題を発見した。にぎわい広場では名簿と操作ツールバーが同じ移動先を提供しているため、テーマ固有のナビを確実に隠すルールを追加した。修正後は下端の重なりがなくなった。

- [844×390 実際のダイスロール後](../artifacts/design-review/round-1/cardboard-844x390-live-roll.png)

実ブラウザで4人のローカル対局を開始し、画面上のサイコロボタンを押した。ロール後に出目、麦畑の発動、プレイヤーごとの収支、市場先頭の施設カードが表示され、ページ全体の横/縦スクロールは発生しなかった。ゲーム状態をシリアライズして比較し、名簿による表示プレイヤー切替だけでは状態が変わらないことも確認した。

追加で10人の終盤 fixture を描画し、10人分の名簿、2つの詳細な街、各街10施設、市場カード4枚、ページ overflow なしを確認した。施設列は横スクロールで操作でき、街9への名簿切替後もゲーム状態のシリアライズ値は一致した。これは密度 stress fixture の確認であり、10人戦を開始から実際に完走した証拠ではない。

### 回帰検証の拡張

`tests/browser/cardboard-table.spec.js` に、横持ちでの実ロールイベント中のレイアウト確認と、10人戦・各プレイヤー10施設・ランドマーク建設済みの高密度 fixture 確認を追加した。名簿の横スクロール、街カードのスクロール、カード絵の最低サイズ、市場表示、表示切替時の状態不変性を確認する。

### 残課題

この画面はカードアートを読める大きさにしたが、市場は縦スクロールを必要とし、全施設を一度に比較する画面ではない。さらに中盤/終盤の実進行、他画面幅、タイトル/保存再開、ランドマーク/勝利演出、4テーマ互換の再検証が必要。追加した Playwright テストはこの Termux 環境では未実行で、Playwright が `process.platform === "android"` を未対応として停止する。CDP による実ブラウザ確認は代替証拠の一部であり、CI の Playwright 結果や実機確認の代替ではない。
