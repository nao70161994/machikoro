# デザイン品質レビュー記録

## 対象と前提

- リポジトリ: `nao70161994/machikoro`
- 対象テーマ: にぎわい広場
- 実施日: 2026-10-09
- 比較基準: 「みんなと街コロ」の完成度。固有アートやキャラクターは使用しない。
- 実ブラウザ確認: Termux 上の Chromium headless を CDP で操作。端末サイズはブラウザエミュレーションであり、物理スマートフォンの実機確認ではない。

## 改善・再レビュー 1

### 発見した問題

844×390 の旧横持ちレイアウトは、4人分の座席を固定位置に押し込み、上下プレイヤーのカードを小さくしていた。左右に余白がある一方、市場とカードの視認性も不足していた。

### 実施した改善

- 761〜1024px、横向き、480px以下では、全プレイヤーの要約を横スクロールの名簿に集約。
- 自分と選択中/手番中プレイヤーの街を表示し、他プレイヤーは名簿選択で切り替え。
- 市場と操作/出目表示を独立した領域に配置し、施設アートを表示。
- 名簿選択ではゲーム状態を変えず、最大2つの街だけを表示する。

### 実画面でのレビューと修正

初回スクリーンショットでPWAインストール案内の状態がゲーム領域を縮める条件を再現した。テスト画面ではインストール案内を正規の dismiss API で閉じ、実際のアプリ動作と fixture の初期状態を混同しないようにした。さらに初回画面では操作ボタンが左端に偏っていたため、操作列を全幅の横スクロール領域にし、各設定項目に明確なボタン面を与えた。

10人戦の密度確認では、個別UIが追加する `#playerNavigation` がインライン `display` によって隠れず、盤面の下端に重なる問題を発見した。にぎわい広場では名簿と操作ツールバーが同じ移動先を提供しているため、テーマ固有のナビを確実に隠すルールを追加した。修正後は下端の重なりがなくなった。

- [844×390 対局開始画面](../artifacts/design-review/round-1/cardboard-844x390-start.png)
- [844×390 実際のダイスロール後](../artifacts/design-review/round-1/cardboard-844x390-live-roll.png)
- [844×390 10人・各10施設・複数ランドマークの密度確認](../artifacts/design-review/round-1/cardboard-844x390-10p-density.png)

実ブラウザで4人のローカル対局を開始し、画面上のサイコロボタンを押した。ロール後に出目、麦畑の発動、プレイヤーごとの収支、市場先頭の施設カードが表示され、ページ全体の横/縦スクロールは発生しなかった。ゲーム状態をシリアライズして比較し、名簿による表示プレイヤー切替だけでは状態が変わらないことも確認した。

追加で10人の終盤 fixture を描画し、10人分の名簿、2つの詳細な街、各街10施設、市場カード4枚、ページ overflow なしを確認した。施設列は横スクロールで操作でき、街9への名簿切替後もゲーム状態のシリアライズ値は一致した。これは密度 stress fixture の確認であり、10人戦を開始から実際に完走した証拠ではない。

### 回帰検証の拡張

`tests/browser/cardboard-table.spec.js` に、横持ちでの実ロールイベント中のレイアウト確認と、10人戦・各プレイヤー10施設・ランドマーク建設済みの高密度 fixture 確認を追加した。名簿の横スクロール、街カードのスクロール、カード絵の最低サイズ、市場表示、表示切替時の状態不変性を確認する。

### 残課題

この画面はカードアートを読める大きさにしたが、市場は縦スクロールを必要とし、全施設を一度に比較する画面ではない。さらに中盤/終盤の実進行、他画面幅、タイトル/保存再開、ランドマーク/勝利演出、4テーマ互換の再検証が必要。追加した Playwright テストはこの Termux 環境では未実行で、Playwright が `process.platform === "android"` を未対応として停止する。CDP による実ブラウザ確認は代替証拠の一部であり、CI の Playwright 結果や実機確認の代替ではない。

## 次に検証すること

- 4テーマの途中切替、オンライン/再接続、保存/Undoの現行回帰状態を確認する。

## 改善・再レビュー 2

### 発見した問題

320pxでは再開と削除が横並びになった一方、390pxでは既存の389px境界を1px超えただけで選択欄・再開・削除が同じ行に入り、ボタンのラベルが一文字ずつ縦に折り返されていた。844×390ではデスクトップ用タイトルの上部装飾が縦空間を使い、中断ゲームの操作が画面下に隠れていた。PCの街並みcanvasも480pxに制限されていた。

### 実施した改善

- タイトル背景を固定ビューポート背景へ移し、左右端とPWA表示中も全画面に描画。
- 街並みcanvasを画面幅に合わせ、描画バッファは最大1920pxに制限。
- 320〜480pxでは保存選択を独立行にし、再開と削除を横並びに固定。削除ボタンも44×44px以上にした。
- 「復旧する世代」を「再開する保存データ」に変更。
- 761〜1024pxの短い横画面ではタイトル装飾を短くし、保存再開操作を初期表示領域へ引き上げた。
- 高コントラスト設定では背景を黒一色にして街並みcanvasを隠す。

### 実画面でのレビュー

保存状態を2世代作り、320×844、390×844、844×390、1440×936で再撮影した。4サイズとも保存選択と再開/削除のラベルが横書きで、再開ボタンと削除ボタンの当たり判定が画面内に収まることを確認した。844×390では保存カード全体とボタンが初期画面に入り、320pxと390pxでは背景の左右余白がなくなった。1440pxでは夜景と街並みが幅いっぱいに広がった。

### 自動確認と残課題

`tests/city-skyline.test.js`、`tests/local-resume-effects.test.js`、`tests/local-resume-view.test.js`、`tests/storage.test.js` は成功し、canvas寸法・全幅描画・1920px上限と保存UI/保存処理を検証した。`tests/browser/title-layout.spec.js` は4つの画面条件で保存再開と描画領域を確認するケースを追加したが、Playwright はこの Termux 環境の `android` プラットフォームで起動できない。各画面の実レンダリングと寸法はChromium CDPで確認しており、ブラウザ自動化specのCI結果は今後回収する必要がある。実機のセーフエリア/PWA通知との重なりもまだ物理端末では確認していない。

## 改善・再レビュー 3

### 発見した問題

320×844の4人戦では、実ロール後も無効な「サイコロを振る」ボタンが建設フェーズの操作列に残り、有効な建設候補/ターン終了ボタンと横幅を取り合っていた。アクションラベルも窮屈で、フェーズに合う操作が直感的に目立たなかった。

### 実施した改善と再確認

有効なターン終了操作が表示されている時は、無効なダイスボタンを隠すようにした。実ブラウザ上で4人戦を開始して実際にロールし、建設フェーズへ遷移することを確認した。修正後の「建設候補を見る」と「建設しないでターン終了」は両方112×44px、各ボタンの内容高42pxで、viewport内の中央タップ位置で入力を受け取る。出目結果と市場カードはページの縦スクロール内で続けて確認できる。

- [320×844 4人戦の実ロール後](../artifacts/design-review/round-3/cardboard-portrait-320-real-roll.png)

### 回帰確認と未達事項

`tests/browser/cardboard-table.spec.js` に320px縦持ちのフェーズ別操作検証を追加した。`npm test` は横持ち盤面とタイトル変更前の時点で実行し exit 0、今回のフェーズ操作に対応する `node tests/ui-card-board.test.js` も成功した。Playwrightの browser spec はTermuxの `android` 未対応で実行できないため、この新規ケースはCIで実行する必要がある。縦持ちは1画面に街/市場を全部押し込まず、上下スクロールで選ぶ構造である。実機操作、2〜4人の長時間完走、5〜10人の実進行、オンライン再接続、ランドマーク/勝利演出、4テーマ間の回帰は未完了であり、このGoalは継続する。

## 改善・再レビュー 4

### 実際のCPU対局

1440×900のChromiumブラウザで、にぎわい広場の2人弱CPU戦を開始から勝利まで実行した。両CPUの手番が進み、108ターンで「CPU（弱）・1」が勝利画面へ到達した。完了時の正本状態は勝者あり、2人ともCPU、ブラウザ例外なし。表示監視ではサイコロ112回、カード発動530回、コイン移動120回、ランドマーク完成演出44回を観測した。中盤・終盤・勝利画面を撮影し、勝利画面では完成した街、ランドマーク、施設数、勝者と再戦導線を確認した。

- [終盤・100ターン付近](../artifacts/design-review/round-4/cpu-match-turn-100.png)

対局中の画面を目視し、中盤でも市場、現在の手番、所有施設、直近イベントを識別でき、終盤には施設アートが街の成長としてまとまって見えることを確認した。勝利画面は大きな街の一覧と結果・再戦操作を同じ流れで確認できる。一方、対局検証は2人戦・弱CPU・1440×900だけであり、4人戦やスマホ画面の実進行、ブラウザのCI spec実行、物理端末は未確認。これだけで商用品質の達成とは判定しない。

追加で同じ固定seedの4人弱CPU戦も開始から完走させた。126ターンで「CPU（弱）・3」が勝利し、監視時間は約8分44秒、サイコロ128回、カード発動453回、コイン移動109回、ランドマーク完成演出52回、ブラウザ例外0件だった。4人の順位・残高と勝者の街を勝利画面で確認した。これはPC幅での実進行確認であり、4人スマホ横持ち、5〜10人CPU完走や対人オンライン対局の証明ではない。
