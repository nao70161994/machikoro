# にぎわい広場：全体盤面への再設計

## 完了基準

- 通常表示で全員の街と中央市場を同時に把握できる。
- 施設数・ランドマーク進捗・残高・手番を街の近くで比較できる。
- 夕暮れの広場と同じ施設アート・街描画を使い、個別カード棚は補助表示にする。
- 2〜4人の320/390/844×390/1440を中心に確認し、5〜10人にも適応する。
- 4テーマの状態不変性、オンライン、Undo、保存再開等の正本を維持する。
- ブラウザ画面と操作、独立レビューを行い、作業ブランチをpushしてPRを作成する。

## 実装中の記録

全員の街を常時描画し、その間へ既存の中央市場を移動した。選択中の1人だけのカード棚は初期状態で閉じた詳細欄へ移し、全席を選べるセレクトを置いた。街の描画はUiBuildMenu.renderTownHtmlを再利用し、発動イベントも全席に渡す。コイン移動の始点・終点は各街の見出しを参照する。ルール・市場在庫・保存データのスキーマは変更していない。

最初の4サイズの外枠配置検証は成功したが、目視で市場カード内部の切れとPCの空白を発見した。外枠のテスト成功を完成とは扱わず、内部の名称・価格・在庫の位置検証を追加した。旧固定パネル向けCSSの競合を整理中。

独立レビューで、横持ちの街が小さく空白が多い点と、単一施設の重複fixtureでは成長を十分に評価できない点を確認した。複数施設・ランドマークを混ぜた画像で再評価する。

第2回ブラウザ確認では、4サイズで全員の街・市場内部の名称価格在庫・詳細街選択・4テーマ往復の状態維持が成功した（計4件）。2人戦の適応も成功。5人/10人の横持ちは市場へ高さを割き過ぎて街が27pxに潰れたため失敗した。基準を緩和せず、多人数の俯瞰サイズと市場のコンパクト表示を調整する。最終の採用画像はdesign-review/2026-10-14-shared-plazaへ画面幅別に保存し、失敗時の画像はローカルartifactへ分ける。

## 追加修正と独立レビュー

市場の内部レイアウトを明示し、PCは複数列、スマホは横送りとした。4人戦の街アートは表示領域全体を使い、行数に応じて縦横比を保って描画する。多人数では街を全席並べ、中央市場を専用のコンパクト表示とする。独立目視レビューでは320/390/844/1440および10人横持ちで全員の街と市場が同時に見え、成長差を比較できた。10人時の街アートは小さいこと、施設22枚時の枚数バッジが多少混雑することは残る制約。

収支・建設の詳細は盤面下の「今回の出目・収支と建設」に分離し、通常時の市場を圧迫しない構造にした。街での発動強調とコイン移動は全体盤面に残る。カード補助パネルを開いた際はスクロール案内を再計測する。

npm testは成功。混在オンライン（4テーマ・途中切替・Undo・再接続）、購入操作、拡大市場からの復帰、ロール演出はブラウザで成功した。最終の14件バッチでは10件成功、4件失敗。失敗は狭幅の固定操作と補助表示のボタン重なり2件、旧アート高さ期待54pxに対して52pxの2件。前者はスクロール余白で修正、後者はアートを60pxへ拡大した。重複した擬似見出しを前提とする古いテストは、実際の市場見出しの表示・位置を確認する検証へ変更した。修正箇所を再確認中。


修正後の7件確認では320/390の補助ボタン操作、4サイズの全体盤面、10人縦持ち、PCの既存回帰が成功した。横持ちの既存回帰1件だけ、市場の縦スクロール属性がautoだったため失敗した。横送り棚では縦方向をhiddenに整理し、PCの複数列だけ縦スクロールを維持した。再確認対象はこの1件と、多人数横持ちの証拠画像の保存。
